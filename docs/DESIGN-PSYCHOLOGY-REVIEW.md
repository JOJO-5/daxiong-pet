# 大熊：设计心理学评审

评审日期：2026-10-05。基线：v1.0.20，以及当前 main（2936964）。

依据：当前界面代码、Linux 原生面板截图、飞盘和拔河交互截图。较早的截图只用于核对布局，当前行为以代码为准。本次是专家启发式评审；以下用户困惑是有依据的假设，尚未经过新用户测试或 A/B 实验。

## 评审结论

优先改善“发现入口 → 明白下一步 → 看见回应”的闭环。大熊已有温暖的视觉基调与低压力陪伴文案，主要问题是按钮、提示和真实状态没有完全对应，用户需要自己推断操作后果。

不建议为解决这些问题重画角色。角色一致性继续遵守根目录 AGENTS.md：原始脸型、毛色、比例与像素风格是基准，接住、咬住和松口的连续性独立验收。

## P1：下一轮优先改

### 1. 首次入口提示容易错过

- **观察**：首次启动的“右键我……”气泡显示 5 秒，显示时就写入已读标记。没有在该提示中提供再次查看的入口。
- **心理依据**：可发现性与识别优于回忆。用户启动软件时可能仍在处理安装窗口，不能假定看到了短暂提示。
- **建议**：提示可主动收起；在第一次成功打开菜单或互动面板后结束新手引导；未操作时仅在合适时机轻提示，不反复弹出。托盘保留“如何和大熊互动”。对 Mac 说明触控板双指点按也可打开菜单。
- **验收**：首次错过气泡后仍能找到玩法；熟悉用户不会持续收到引导。让首次使用者无口头指导找到一个游戏，观察实际卡点。
- **定位**：`src/App.tsx:85`；`src-tauri/src/main.rs:324`。

### 2. 主按钮必须对应当前状态

- **观察**：追逐、叼回和松口阶段仍可点击“拿出球/飞盘”“抛一球/扔飞盘”；拔河进行中仍可点击“拿出绳子”。这些命令会启动或重置互动。飞盘返回后的提示说可以再扔，但按钮标签没有变化。
- **心理依据**：用户根据按钮文案建立操作预期；同一按钮在不同状态下悄悄重置游戏，会削弱可控感。
- **建议**：未开始时突出“扔一次”，正在追逐时显示“大熊正在捡回来”，返回后改为“再扔一次”，并从真实落点继续。追逐和松口期间避免用普通开始按钮重置；“结束互动”保持可用。拔河拿出绳子后，将主提示改为“按住橙色绳环，向外轻拉”，完成一轮后提示“再拉一轮”。普通重复动作不增加确认弹窗。
- **验收**：各阶段按钮后果与文案一致；连点不会导致意外重置；按钮重扔和拖动重扔遵守同一落点规则。
- **定位**：`src/PlayPanel.tsx:55`、`:56`、`:66`、`:68`；`src-tauri/src/engine.rs:386`。

### 3. 喂食不应成为隐含的结束游戏按钮

- **观察**：“喂一块饼干”始终是醒目的整行绿色按钮，与游戏动作争夺视觉优先级；后端喂食会取消玩具和练习。
- **心理依据**：视觉显著性引导点击，结果却包含未写明的副作用，容易产生误操作。
- **建议**：游戏期间把喂食降为次要操作；如果保留中断语义，明确写“结束游戏，喂块饼干”。练习完成时突出已有的“奖励这次指令”，让普通喂食与训练奖励容易区分。切换游戏后用短反馈说明“已收起飞盘，准备拔河”。
- **验收**：用户在点击前能判断当前游戏是否会结束；奖励入口的后果清楚。避免每次切换都询问确认。
- **定位**：`src/QuickFeed.tsx:12`；`src/PlayPanel.tsx:53`、`:72`；`src/TrainingPanel.tsx:32`；`src-tauri/src/engine.rs:413`。

### 4. 反馈放在动作附近，并提供可理解的恢复办法

- **观察**：昵称保存后更新数据，但缺少明确的成功提示；部分异常直接显示 `String(error)`；游戏通用错误位于面板底部，可能需要滚动才能看到。
- **心理依据**：及时反馈帮助用户确认动作已生效；靠近操作的反馈减少视线搜索和重复点击。
- **建议**：昵称保存后在输入框附近显示“记住啦，以后叫你 ××”；错误放在相关按钮旁，写清“发生了什么、可以怎么继续”，技术细节折叠。记忆恢复会重新开始记录，应展示备份位置及重置范围，并在执行前确认这一后果。
- **验收**：操作成功、失败和处理中都可辨认；错误无需滚到底部寻找；重置前能理解哪些记录将重新开始。
- **定位**：`src/CompanionPanel.tsx:28`、`:44`、`:47`；`src/PlayPanel.tsx:45`、`:75`。

## P2：随后改善

### 5. 操作提示跟着桌面玩具走

- **观察**：飞盘和球较小，用户需要在面板与桌面之间转移注意；拔河已有橙色绳环和悬停说明，这是好的基础。
- **心理依据**：空间对应关系降低理解成本；费茨定律提示小目标与较长移动距离会增加指向难度。
- **建议**：保留玩具的原有视觉大小，评估略大且不遮挡桌面的命中区域。可操作时在玩具附近短暂提示“拖住，松手扔”；绳环悬停时强化轮廓，按住后立即提供受力反馈，松手显示休息状态。关闭按钮也应扩大命中区域，并将辅助标签统一为“收起面板”，与“结束互动”区分。
- **验收**：触控板和高 DPI 场景也容易抓住玩具；扩大区域不会抢占正常桌面点击；关闭面板的结果符合说明。
- **定位**：`src/TugRope.tsx:13`；`src/PlayPanel.tsx:52`、`:97`；`src-tauri/src/main.rs:320`。

### 6. 主界面减少无关信息竞争

- **观察**：当前游戏卡片同时展示动作、连续次数、接回次数、玩法说明以及“偶尔叼球逗你追”偏好。
- **心理依据**：当前目标之外的信息增加扫描负担。五个游戏本身不足以证明选择过载，不需要凭数量砍掉玩法。
- **建议**：卡片优先保留“当前状态、下一步操作、结束入口”；稳定偏好放到“记忆与偏好”。次数收束为一个次要信息区。接球、飞盘、拔河保持相邻，指令和找零食在视觉上形成另一组；保持快速切换。
- **验收**：扫一眼能找到下一步；收起信息后仍能随时找到偏好和统计。
- **定位**：`src/PlayPanel.tsx:53`、`:59`、`:60`、`:62`。

### 7. 陪伴记忆以关系为主，数字为辅

- **观察**：“熟悉程度 9/20”、进度条和互动次数突出；喂食有秒级倒计时。对部分用户，这可能把陪伴变成刷进度。
- **心理依据**：显眼的外部指标会改变用户关注的目标；这是需要验证的风险，不等于数字一定有害。
- **建议**：关系阶段与真实发生过的共同经历优先展示，计数放到可展开的记录中。冷却文案可以先说“大熊还在嚼，稍后再喂”，时间作为辅助信息。保留“暂时离开，感情也不会变淡”和“离线不遗忘”；不新增连续签到惩罚、饥饿催促或离线掉好感。记忆文案必须来自实际记录，不能虚构共同经历。
- **验收**：用户清楚不需要每天打卡；喜欢数字的人仍能查看记录；冷却期间知道何时可再次操作。
- **定位**：`src/CompanionPanel.tsx:40`、`:42`、`:46`；`src/QuickFeed.tsx:12`；`src/TrainingPanel.tsx:29`。

### 8. 陪伴感需要兼顾工作中的注意力

- **观察**：已有专注时停止玩具、偶遇不打扰、减少近期重复台词等机制；系统减少动态效果仅覆盖部分 CSS 动画。
- **心理依据**：变化和运动容易捕获注意。桌宠需要允许用户调节这种刺激，同时保持角色可辨认与动作连续。
- **建议**：明确区分普通陪伴与安静陪伴；安静模式降低闲聊及偶遇频率，用户主动互动仍获得反馈。统一检查系统减少动态效果偏好的覆盖范围。咬住、落地、松口必须保留必要的因果反馈，不能为了减少动画让道具瞬移或切换角色外观。
- **验收**：专注期间没有主动催促；主动操作仍有回应；减少动态效果时无新增穿模、瞬移或角色漂移。
- **定位**：`src/EncountersPanel.tsx`；`src/App.tsx:103`；`src/styles.css`；根目录 `AGENTS.md`。

## 建议实施顺序

1. 先改状态按钮、喂食中断说明、就地反馈：直接减少现有交互困惑。
2. 再补首次使用引导和桌面玩具提示：提高入口与手势的可发现性。
3. 最后调整信息层级、记忆呈现和安静陪伴：用首次使用者观察检验取舍。
