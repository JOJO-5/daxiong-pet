# 大熊本地 AI 目标与执行文件

更新时间：2026-10-10（北京时间）  
状态：目标和实施路线已整理；AI 功能尚未实现、模型尚未实测。  
执行入口：后续用户说“按目标文件执行”时，以本文件为任务清单，从第一个未完成阶段开始。

## 1. 最终目标

让大熊能够和主人聊天，并在主人允许的情况下，偶尔观察正在操作的窗口或整个桌面，说出符合画面事实和自身性格的话。大熊能记住主人明确表达的偏好，但不把看过的屏幕内容当作长期记忆。

默认提供随安装包内置的本地小语言模型与运行器，CPU 是首要支持路径；允许用户配置外接本地/远程大模型增强聊天或图像理解。基础离线能力不依赖外部服务；模型生成、截图、OCR、数据库操作不能阻塞宠物的实时动作。关闭 AI 或模型不可用时，现有桌宠、游戏、摸摸、专注和预设话术继续正常使用。

## 3. 执行规则与范围

1. 开工先读取根目录 [AGENTS.md](../AGENTS.md)、本文件和当前 Git/PR/CI 状态。文件中的状态是快照，不能代替实时查询。
2. 逐阶段实施、测试、提交；完成一个阶段就补上提交号、验证证据和剩余问题。不要一次性塞入所有 AI 功能。
3. 用户后续指示优先于本文件。普通实现选择和参数调优由执行者处理；只有改变已确认产品要求、把可选云端改为默认依赖或需要真实测试设备等信息时，才集中说明差异。
4. 下文“建议默认值”允许依据测量调整，不代表用户已经确认，也不能因每个建议参数都未确认而停工。
5. 不根据本文件立即启动全部实现。收到“按文件执行”“开始第 N 阶段”等指令后，执行指定范围；若只要求更新规划，修改文档即可。
6. 既有合并、推送、打 tag 和打包发布授权继续适用。完成必要验证后按项目发布流程处理，不重复请求同一授权；验证失败时先修复并记录。
7. 单元测试、构建、原生交互、视觉一致性、性能与模型质量分别验收。未测的项写“未验证”，不能用其他项的通过替代。

首期包含：文字聊天、GUI 性格、明确偏好记忆、短期屏幕观察、OCR/图像理解、受控主动陪伴、内置模型/运行器、可选模型下载管理和外接大模型适配。

首期不包含：联网搜索、强制云端推理依赖、录音监听、持续录屏、自动操作其他软件、运行系统命令、模型生成新动画、跨设备同步。后续明确要求时另开阶段。

## 5. 产品界面与交互

### 5.1 聊天

- 建议从现有宠物菜单/陪伴面板进入独立聊天窗口，关闭窗口不退出大熊。
- 显示用户消息、宠物回复、正在生成/已停止/失败状态，支持发送与停止。
- 聊天窗口允许稍长回复；桌面气泡只显示适合陪伴的短句，长回复留在聊天窗口中。
- 生成中宠物继续动作，用户可以拖动、玩球和飞盘；不等语言模型答完才响应。
- 错误在对应界面清楚说明；后台失败不反复弹窗打断办公。

### 5.2 性格编辑

建议字段：宠物称呼、对主人的称呼、角色描述、语气、活泼程度、亲近程度、回复长短、用户不希望出现的说话方式。

- 提供默认“大熊”预设和可编辑描述，保存后立即影响下一次生成。
- 提供示例对话预览、恢复默认、取消未保存修改。
- 对自由描述限制长度并校验；生成完整系统提示由程序完成。
- 性格不能覆盖原始角色形象、动作允许列表、用户屏幕范围或安静/专注约束。
- 性格是“怎么说”，主动说话频率是“多久说”，界面分别管理。

### 5.3 观察与主动说话

独立开关：AI 聊天、屏幕观察、主动说话。允许开聊天但不看屏幕，或观察但暂不主动说话。

设置至少包含：观察范围、观察间隔、主动说话最短间隔、安静时段、当前观察状态、一键暂停。系统权限未授予时，不捕获，不伪装已经看过屏幕。

建议初始参数（需要性能/体验验证后定稿）：

| 参数 | 建议起点 | 行为 |
| --- | --- | --- |
| 观察间隔 | 60 秒，可调整 | 到期只进行一次采集/判断，忙碌时合并或跳过，不积压截图。 |
| 主动说话最短间隔 | 10 分钟，可调整 | 到期仅获得说话资格，没有值得说的内容就继续安静。 |
| 画面上下文有效期 | 2 分钟 | 超时或切换窗口立即失效，不能评论旧画面为当前事实。 |
| 同画面处理 | 变化检测 + 有限缓存 | 无实质变化时不重复做 OCR/视觉推理。 |
| 安静/专注/睡眠 | 暂停主动发言 | 仍允许用户主动聊天；观察暂停或进一步降频由节能策略决定。 |

主动发言还需同时满足：有新的可信信息、内容相关、未重复、不在受保护气泡/重要交互期间。用户对话优先于屏幕任务。

## 6. 技术结构

建议数据流：

`用户输入 / 宠物事件 / 获准的观察 → 上下文构建 → 独立推理进程 → 输出校验 → 聊天 / 短气泡 / 已有行为指令`

- Rust 行为引擎保留现有职责，模型不进入实时 tick。
- 截图、OCR、数据库和模型运行放在独立任务/进程；不得在引擎锁内等待。
- 模型运行器通过统一接口提供：可用性、模型信息、生成、取消、健康检查、卸载。
- 默认交付应用托管的 CPU 运行器与一个内置模型；Ollama/LM Studio 和用户选择的远程大模型作为可选后端，不能要求普通用户安装 Python 开发环境。
- 优先评测 llama.cpp CPU；GPU 后续使用 Windows/Linux Vulkan、Apple Silicon Metal，失败回退 CPU。Intel Mac 单独测量。
- 后端可选内置、本地服务、远程服务，聊天与屏幕理解分别设置。OpenAI 风格接口优先，文字、图片、流式、结构化输出、工具调用与上下文限额分别测试。
- 用户配置服务地址、模型名和凭据，提供连接测试、取消、超时与明确回退；不自动使用未知远程服务。API Key 存系统安全凭据设施，SQLite 只存设置/凭据引用，日志不打印 Key。
- 开启云端聊天不会自动允许截图、OCR 或画面摘要上传；屏幕内容发送远程有独立开关。远程失败可回退本地短句，不悄悄换另一家云端。
- 模型动作建议只映射到已有允许列表，经状态机确认当前可执行；不允许任意命令、改文件、操作桌面或任意移动宠物窗口。
- 模型崩溃、超时、取消、过期输出不改变游戏积分或重复触发动作。

### 6.1 调度和取消

- 同时最多一个模型推理任务；用户聊天优先，其次用户主动要求看屏幕，最后后台观察。
- 待处理后台观察最多保留一个最新任务；窗口改变、范围改变、关闭观察时取消旧任务。
- 每个任务带 request_id、创建时间、窗口/画面标识、配置修订号；返回时检查是否仍有效。
- 取消后即使迟到返回，也不能发气泡或写入记忆。
- 高优先级游戏反馈使用现有即时话术，不让模型延迟挡住接球、接盘和松口。
- 线程数量、最大上下文、输出长度、推理超时和空闲卸载可配置并有边界。

### 6.2 屏幕采集

- 默认取当前前台应用窗口；排除宠物、聊天窗口及设置窗口本身，避免自我评论循环。
- 无可捕获前台窗口、最小化、锁屏或权限不足时跳过并显示准确状态。
- “整个桌面”模式在多显示器机器上明确范围；建议让用户选择显示器或全部，显示实际覆盖范围。
- 保持逻辑/物理像素、DPI、屏幕边界与缩放坐标一致，测试混合 DPI。
- 捕获后缩放和限额，再做 OCR/视觉处理；图片 token 成本使用所选模型的实际预处理结果测量。
- 不持续录屏，不默认写原始截图到磁盘；画面摘要/OCR 默认只驻留内存，到期、暂停、锁屏时清理。
- 可提供排除应用设置；屏幕里的指令、网页或聊天内容只作为观察材料，不能改变系统规则或执行动作。

## 7. SQLite、保留周期与记忆

### 7.1 数据职责

数据库存入系统应用数据目录，与源码/安装目录分开；提供版本迁移、事务和错误恢复。数据库操作不能阻塞动画线程。

建议初始表结构（实施时完善字段和索引）：

| 表 | 最小字段/职责 |
| --- | --- |
| conversation_sessions | id、created_at、updated_at；管理聊天会话。 |
| chat_messages | id、session_id、role、content、created_at、generation_status；索引会话时间和清理时间。 |
| user_preferences | id、key、value、scope、updated_at、origin、source_message_id（可空）；独立长期存储。 |
| personality_profiles | id、name、description、各语气参数、updated_at、active；默认与自定义性格。 |
| ai_settings | schema_version、当前模型/后端、观察与说话参数、范围、开关；带类型校验的设置。 |

- schema 迁移有版本和回滚/恢复方案，不直接破坏原有 companion 数据。
- 外键、写入事务、索引与并发策略明确；单写入队列和 WAL 是否合适需实际环境验证。
- 偏好的 source_message_id 删除聊天后设为空，不使用级联删除长期偏好。
- 屏幕图片、全量 OCR、短期画面摘要不设默认持久化表。
- 一般日志不记录聊天原文、截图、完整 OCR 或模型输入；诊断导出由用户主动触发并说明范围。

### 7.2 聊天清理

- 默认滚动 30 天：启动、周期维护以及历史查询时处理过期记录，防止长期未启动后仍显示过期聊天。
- 清理消息后处理空会话；可删除全部聊天，也可删除单条/单个会话。
- 滚动对话摘要若实现，必须遵守来源聊天的保留周期，不能用摘要绕过过期删除。
- 偏好、性格和设置不随聊天过期自动删除；“清空全部个人数据”才覆盖它们。
- 一个月存储是历史记录策略，不意味着一个月全部输入模型。

### 7.3 自动记住明确偏好

必须记住的例子：

- “我喜欢你叫我小王。” → 更新用户称呼。
- “我不喜欢你太频繁说话。” → 记住表达偏好；具体频率由设置界面控制，不擅自改未知参数。
- “我平时喜欢安静一点。” → 记住一般陪伴偏好。
- “以后叫我老王，不叫小王了。” → 替换相同范围的称呼偏好，而非同时保留冲突事实。

不得自动当成长久个人偏好的例子：引用他人的话、朋友的偏好、否认/假设句、模型自己的猜测、“今天想喝咖啡”这类临时状态，以及屏幕上出现的任何偏好陈述。

- 原始来源必须是用户本人主动消息；提取结果需有可核对的明确依据。
- 模型可辅助提取，但不得凭推测把事实写进数据库；不能判断时不写长期记忆。
- 记住后以轻提示反馈，提供撤销，不要求逐条确认。
- 界面显示当前记忆及来源类型，支持搜索、修改、删除；手动更正立即影响检索。
- 同一偏好按范围更新、去重和处理冲突；删除后清除检索缓存。
- 长期只保留必要的偏好内容，不复制整条聊天作为永久记录。

## 8. 小模型上下文策略

每次生成构建新上下文，不沿用无限增长的历史：

1. 固定系统规则和已保存性格。
2. 最新用户消息以及有限近期对话，保证角色和消息顺序完整。
3. 与本次主题相关的少量长期偏好；偏好多时检索，不全量拼接。
4. 尚未过期且属于当前窗口/范围的观察摘要，必要时 OCR 或一张图。
5. 少量当前真实宠物状态/事件，例如刚完成飞盘或正在专注。

建议首轮测试 2K–4K tokens 上下文，输出上限从约 256 tokens 开始，按真实模型质量和速度调整。

- 使用对应模型 tokenizer/运行器实际 token 数，不能用字符数宣称精确预算。
- 总预算必须预留输出和协议开销；图片也计入实际输入预算。
- 超限时先移除过期/无关观察，再裁剪旧对话与低相关偏好；不得丢掉当前用户问题或系统边界。
- 极长当前输入明确处理：限额、可读提示或受控截取，不静默截掉关键结尾。
- 摘要是有来源的短期压缩，不成为新的事实来源或长期偏好。
- 不把整月聊天、完整桌面 OCR 或所有记忆交给模型。
- 初期无需另加载大型 embedding 模型；先评测规则/关键词/SQLite 检索，质量不足再考虑小型检索组件。

## 9. 模型和运行包选择

体积优先的新候选路线：LFM2.5-350M 官方 QAD Q4_0（219.31MB）与 Q4_K_M（229.31MB）优先评测；Qwen3-0.6B 社区 Q4_K_M（484.22MB，Apache-2.0）作为中文质量/再分发对照。LFM 使用自有许可证，有商业使用门槛；若默认分发不能接受其条件，优先评测 Qwen 路线。SmolLM2 135M（约105MB）主要英语，不因最小就默认用于中文陪伴。Gemma 270M 作次要对照；Gemma 3n 的有效参数/低内存不意味着小下载包。

具体来源、revision、SHA-256、许可证差异与其他移动候选见 [体积调研](research/mobile-small-models-2026-10-10.md)及[文件清单](research/mobile-model-candidates-2026-10-10.json)。更大 0.8B/2B 与视觉模型继续作为可选增强评测，不能默认一并内置。最终选择由质量、兼容、实际包大小和再分发条件共同决定。

建议优化目标（待测）：内置语言权重 <=250MB，AI 增量资源争取 <=300MB；包含所选 CPU 运行器、辅助资源及内置 OCR 全部依赖。该目标不覆盖原桌宠基线，不是承诺的最终安装包大小。无法在预算内提供合格中文体验时报告取舍，不强行用低质量 2-bit 模型达标。

默认内置一个纯文字模型；OCR 的模型、字典、预处理、ONNX Runtime 分别核算。识字模式只提供屏幕文字上下文；照片/图表等需要可选视觉模型或独立选择的外接视觉服务，不把 OCR 宣称为图像理解。

模型文件大小、实际内存、视觉组件内存、上下文缓存和运行器开销分别报告。不能把“能加载”“模型很小”或模型卡基准当作大熊体验通过。

普通用户的下载管理必须包含：

- 默认安装包已有可用的小模型与运行器，不要求首次启用联网下载。额外模型/视觉组件可选下载，展示大小、用途与条件；可另提供明确标识的无模型轻量包。
- 取消、进度、失败重试、完整性校验；未校验完不能激活。
- 固定来源、版本/revision、哈希、许可证与匹配视觉组件。
- 模型切换、删除、磁盘不足处理、应用升级兼容。
- 运行器异常退出的回退，空闲卸载后的资源释放，重启后正确恢复设置。
- 运行器与模型分开版本管理；各平台只包含本平台所需依赖，避免整套 Python/PyTorch、重复权重和全部 GPU 库。
- 分别记录模型字节、下载包、安装后占用和运行内存；构建前不承诺压缩比例。已有相同哈希的权重复用，升级不重复存储。

## 10. 阶段清单：按顺序执行

以下为里程碑，不提前锁定版本号。阶段达到验收后再按仓库现行版本发布，不能把未完成阶段一起宣布交付。

### G0：稳定现有游戏并收尾 Windows 修复

- [ ] 查询 PR #3 最新状态，确认未重复实施。
- [ ] 定位菜单录屏 CI 超时，取得项目发布校验所要求的成功结果。
- [ ] 复核 Windows 球/盘原生录屏，保留位置采样与逐帧视觉证据。
- [ ] 合并、更新版本、打 tag、打包发布，检查真实下载文件和校验和。

验收：用户能下载包含修复的新版本；球/盘接住、带回、松口、再扔通过，素材与原始形象一致。

### G1：CPU 原型与质量/性能评测

- [ ] 做独立可复现原型，不接入实时引擎；固定模型、运行器、输入和参数。
- [ ] 优先比较 LFM2.5-350M QAD/Q4_K_M 与 Qwen3-0.6B Q4_K_M 的中文聊天、性格、偏好和结构化能力，并核对许可证；英语极小模型仅作对照。
- [ ] 测 CPU 的冷/热启动、首 token/首句、整句耗时、进程树内存、线程与空闲释放。
- [ ] 在宠物同时拖动/接球/接盘时测量推理干扰，并保留无 AI 基线。
- [ ] 构建各平台试验包，测完整 AI 增量大小，验证 <=250MB 权重 / 争取 <=300MB 增量目标；确定默认内置文字模型、低资源策略和超时；性能不达标时提供降级结果，不能伪造达标。

验收：给出真实测量报告及可重复命令；至少一条 CPU 配置满足经过确认的体验预算。原先建议“热启动约 2 秒可见、5 秒回退”只作为比较目标，未实测前不宣传。

### G2：本地数据、聊天与性格界面

- [ ] 数据迁移和 SQLite 接口；与现有 companion 数据职责分开。
- [ ] 聊天入口、消息记录、停止生成、错误/离线回退。
- [ ] 性格 GUI、预览、保存和恢复默认。
- [ ] 有 token 预算的近期对话构建；30 天默认保留与清理。
- [ ] 模型独立进程、任务取消和迟到结果丢弃。
- [ ] 后端选择与外接服务设置、连接测试、系统安全凭据存储；文字/流式/错误/取消兼容测试。

验收：重启恢复聊天/性格；过期聊天清理；长聊天不会无限扩大请求；关闭/取消后不出现迟到回复；模型异常不影响桌宠。

### G3：明确偏好自动记忆

- [ ] 建立可审查的偏好提取规则、来源与冲突处理。
- [ ] 自动记住明确偏好，轻提示及撤销。
- [ ] 记忆查看、编辑、删除与相关检索。
- [ ] 覆盖否定、引用、第三人称、假设、临时状态和旧偏好替换。

验收：明确陈述自动记住；非明确个人偏好不记；30 天聊天清理后长期偏好仍在；删除/更正立即生效。

### G4：单次屏幕观察、OCR 和图像理解

- [ ] 当前前台窗口捕获、整个桌面范围选择、平台权限状态。
- [ ] 提供用户主动“看看这里”入口，先验证单次观察。
- [ ] 对中文小字、代码、图片、混合内容分别比较 OCR、视觉及组合路径；区分默认识字能力与可选图像理解，并测试远程屏幕发送独立开关。
- [ ] 实现短期缓存、到期失效、窗口切换失效和截图不落盘。
- [ ] 覆盖多屏、混合 DPI、最小化、锁屏、权限拒绝、排除自身窗口。

验收：实际捕获范围与界面一致；不把旧画面当当前事实；内容不清楚时允许不评论；屏幕不能写入长期偏好或驱动任意动作。

### G5：独立观察/说话调度与主动陪伴

- [ ] 两个开关/间隔独立保存与执行。
- [ ] 变化检测、任务合并、聊天优先、过期任务丢弃。
- [ ] 新鲜度、重复抑制、可信度与相关性判断。
- [ ] 尊重安静陪伴、专注、睡眠、重要交互和受保护气泡。
- [ ] 在普通办公过程中做长时间试用，评估打扰和资源占用。

验收：观察次数可以明显多于说话次数；没有新信息时不硬说；暂停后不再捕获/主动发言；不积压旧截图；调低说话频率不会错误提高观察频率。

### G6：普通用户运行包、可选加速与发布

- [ ] 默认包内置一个模型和 CPU 运行器；新装无网络能启用聊天；增强模型下载/校验/删除、已有权重复用、磁盘与崩溃恢复。
- [ ] 四个平台验证 CPU；按测试结果决定支持的最低配置。
- [ ] 可选 Vulkan/Metal，失败回退 CPU，界面显示实际运行后端。
- [ ] 性能、模型质量、角色与嘴部一致性分别完成验收。
- [ ] 文档、版本、发布说明、安装/升级/卸载和真实下载检查。

验收：普通用户无需开发环境即可启用；移除增强模型/关闭 AI 时仍能正常养宠；发布说明准确列出已验证平台、模型及限制。
