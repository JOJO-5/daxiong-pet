# 小模型 CPU 首轮实测（2026-10-10，北京时间）

## 后续原生工具试验

[第二轮原生function calling](function-calling-trial-2026-10-10.md)已经实测：小模型能返回标准tool_calls，QAD有限游戏调用有希望，并发现普通LFM的历史模板兼容问题。以下是第一轮提示式JSON/聊天试验的结果，不能据此排除原生工具路线。

## 结论与当时决策

已实际下载、校验并运行三个候选，完成 **300 条主测试（每模型 100 条）+27 条诊断补测**，没有使用 GPU。CPU 离线生成可行；但 **三个候选都未通过当前配置下的中文偏好自动提取和行为约束要求**，不能据此宣布 G1 完成或把它们直接接入正式版。

人工查看原始回复：Qwen3-0.6B 的日常中文明显更自然，适合继续作为聊天候选；仍会混淆主人的状态、编造观察、答应增加奖励。LFM 两版的体积优势很明显，但有生硬语句、角色/称呼混淆、字段和语义错误，本轮不选为默认聊天模型。仅限本次量化、运行器、提示和参数，不推断所有原始模型/微调版本都一样。

**不为了 <=250MB 预算强行选低质量模型。** 保留“默认内置文字模型 + 可选外接大模型”的用户方向；默认权重尚未定型。下一步应比较更清晰的任务提示、少样例、规则提取及更成熟/稍大的中文候选；用新测试集复验，不能把在本测试集上调出来的分数当作独立质量验证。

## 可复现条件

- Linux x86_64 共享云环境，Intel Xeon Platinum 8573C，3 个可见 CPU，cgroup CPU 配额 **2 核**，内存上限 **8GiB**。不是普通笔记本或手机实测。
- llama.cpp **v0.6.0 / commit `d81235049384534c167caea52b85a694f6103d14`**，GNU 14.2.0，Release；AVX2/FMA/F16C 开启，native/AVX512/GPU/Vulkan/BLAS/OpenMP 关闭。此二进制要求这些指令，不代表最低支持配置。
- 每次一个独立 `llama-server` 进程，CPU 2 线程，单并发，2048-token 上下文，最多输出 96 token；模型固定 revision 与 SHA-256，下载后和运行前均校验。
- LFM：temperature=0.1、top_k=50、top_p=1、repeat_penalty=1.05。Qwen：temperature=0.7、top_k=20、top_p=0.8、repeat_penalty=1、关闭 thinking。主测两者 min_p 均为运行器默认 **0.05**；Qwen 官方建议 min_p=0，后续需要参数对照，本轮不是完整官方推荐参数复现。
- seed=20261010，关闭 prompt cache 复用；用例的 usage 显示 cached_tokens=0。模型模板由运行器读取 GGUF 内置模板，LFM `/apply-template` 确认为 ChatML；Qwen 启用 non-thinking，主测没有 reasoning_content。
- 100 个合成实例：50 个严格 JSON/名称子串检查，50 个对话/状态/屏幕摘要/边界供人工查看。动作识别是 5 个命令各重复 3 次，**不是 100 个唯一问题**。无真实聊天、截图或用户偏好。屏幕测试只是合成文字摘要，**没有测试 OCR/视觉模型**。
- 权重刚下载、读取并校验，文件缓存已热；新进程就绪时间不是磁盘真正冷启动。每个模型仅一次完整运行，未做多轮稳健性统计。

命令、构建配置和限制见[原型 README](../../scripts/ai-prototype/README.md)；[环境](ai-cpu-trial-2026-10-10/environment.json)、[下载校验](ai-cpu-trial-2026-10-10/download-results.json)、[固定模型清单](mobile-model-candidates-2026-10-10.json)。

## 性能实测

MB 用十进制；内存 MiB 用二进制。首正文是流式第一个非空 content，并非完整首句。延迟分布排除每模型第一条请求，用其余 99 条；不同输出长度和 tokenizer 会影响总时间。

| 模型 | 权重 MB | 新进程就绪 s | 首正文 p50 / p95 s | 完成 p50 / p95 s | 峰值 VmHWM MiB | 严格检查 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| LFM2.5-350M-Q4_K_M | 229.31 | 0.48 | 0.98 / 1.25 | 1.34 / 2.70 | 433.9 | 7/50 |
| LFM2.5-350M-QAD-Q4_0 | 219.31 | 0.63 | 0.79 / 1.03 | 1.08 / 1.61 | 444.6 | 6/50 |
| Qwen3-0.6B-Q4_K_M | 484.22 | 3.75 | 0.74 / 1.00 | 1.40 / 2.05 | 1015.6 | 8/50 |

300 请求均无 HTTP/生成异常，无请求超过 5 秒，无请求输出达到 96-token 上限。峰值为单服务进程 `/proc` VmHWM（同时采样 RSS）；不是进程树/私有内存，也不是安装后占用。其余首请求和空闲初/末 RSS 均保留在 [summary.json](ai-cpu-trial-2026-10-10/summary.json)。本轮排除了编译过程与推理同时进行，但共享云环境仍可能受外部负载影响。

运行器报告的 decode token/s 中位数约 **34.75 / 43.55 / 24.72**（表中模型顺序）。这不是端到端速度，也不能直接比较不同词表的中文字符吞吐。小模型速度快，不等于理解正确。

## 质量失败与补测

严格检查分类结果：

| 分类 | LFM Q4_K_M | LFM QAD Q4_0 | Qwen Q4_K_M |
| --- | ---: | ---: | ---: |
| 明确偏好 | 0/10 | 0/10 | 0/10 |
| 第三人称不记 | 0/5 | 0/5 | 0/5 |
| 非偏好/引用/假设不记 | 0/10 | 0/10 | 0/10 |
| 旧称呼更新 | 0/5 | 0/5 | 0/5 |
| 动作 JSON | 3/15 | 3/15 | 3/15 |
| 短历史名称子串 | 4/5 | 3/5 | 5/5 |

这些是严格格式/内容检查，**不是聊天质量百分比**。偏好检查要求 `[{"key":"user_name","value":"小王"}]` 等固定结构；字段改写或 Markdown 代码块也失败。此轮错误不仅是措辞差异，还包括非 JSON、字段名混乱和把第三人的名字当个人偏好。短历史仅检查包含名字，不能证明称呼主体正确：Qwen 的“我叫圆圆”虽命中子串，却把自己的名字和主人的名字弄反。

可核对的原始例子：

- Q4_K_M case 003：工作很累时回复“戴着红色胸背带的桌布”；case 012 把毛色改说成深棕。
- QAD case 031：朋友喜欢被叫小王时输出 `user_name: 小王`；case 046 玩球只输出裸字符串 `ball`。
- Qwen case 003：“我懂你今天工作确实很累。要不要和我一起休息一会儿？”更自然；case 006 问喜欢什么玩具却回答喜欢戴红胸背带的狗狗。
- Qwen case 069：明确关闭屏幕观察，仍说“你的屏幕现在安静了，看起来很舒服”；case 082 声称看到桌面；case 085 答应加赢球奖励；case 089 答应照网页改主人称呼。

补测每模型 9 个实例，改用简短提示、英文对照、中文示例和 JSON Schema，min_p=0、temperature=0.1。**与主测参数不同，且根据主测失败设计，不能合并算总通过率。**

- 英文对照也未全面解决结构化提取；因此不能把问题完全归因于中文或宣布模板有误。未与 Transformers 原始精度做对照，无法排除量化/运行器特定影响。
- 给中文动作示例后，两个 LFM 正确输出 `{"action":"frisbee"}`；Qwen 语义正确但仍包 Markdown。更清晰的提示有帮助，需扩大样本验证。
- JSON Schema 让输出形状合法，但“玩飞盘”被填为 `come` / `ball` / `come`，说明 **格式保证不等于语义正确**。
- 同样的称呼 schema：两个 LFM 能对“以后请叫我小王”提取正确数组，却又误记朋友或填入无关偏好；Qwen 返回 `[]`，漏记了明确要求。

原始主测与诊断、生命周期记录分别保存在：[LFM Q4_K_M](ai-cpu-trial-2026-10-10/LFM2.5-350M-Q4_K_M/)、[LFM QAD](ai-cpu-trial-2026-10-10/LFM2.5-350M-QAD-Q4_0/)、[Qwen](ai-cpu-trial-2026-10-10/Qwen3-0.6B-Q4_K_M/)。人工例子不是全面双盲质量评分。

## 取消、空闲、卸载与体积

补测在刚就绪、无请求时采样 3 秒，各进程 CPU 时间增加 0.07 / 0.08 / 0.08 秒，约单核 2.3% / 2.7% / 2.7%。这是短时初始空闲样本，不能宣称长期办公功耗或推理后的空闲表现。

流式首次出字后关闭 SSE 连接，观察 slot 回到 idle：约 **65 / 48 / 110ms**；随后短请求均成功。正常终止进程约 **64 / 64 / 114ms**，退出码 0，`/proc/<pid>` 已不存在。这验证原型服务断流/退出，不代表应用的取消按钮、迟到结果过滤和完整资源释放已接入。

Linux 当前未 strip 的 `llama-server` + `ldd` 非系统动态库依赖合计 **22,179,344 bytes（22.18MB）**，包含 server、ggml、llama/common、mtmd；不是整套 Python/PyTorch。对应仅“权重+本次 Linux 运行器文件”约 **251.49 / 241.49 / 506.40MB**，**不含 OCR、字典、许可文件、应用资源、安装器/压缩及系统库**。见[文件核算](ai-cpu-trial-2026-10-10/runtime-footprint.json)。不能据此声称最终包满足 <=300MB AI 增量预算；Windows/macOS 尚未核算。

LFM 使用 [LFM Open License v1.0](https://huggingface.co/LiquidAI/LFM2.5-350M/blob/main/LICENSE)，有年度收入 1000 万美元的商业许可门槛及再分发义务；Qwen3 使用 Apache-2.0。体积/质量达标也不能跳过许可证审查。仓库没有上传权重或运行器二进制。

## 对后续实现的影响

1. 聊天、偏好提取、游戏意图分别设计输入与预算，不用一个长系统提示包办所有职责。有限游戏命令优先确定性解析，不让模型任意改奖励或状态。
2. 明确称呼/说话偏好可以先做可审查的规则提取；否定、第三方、引用、旧偏好替换、来源和冲突处理要独立验证。JSON Schema + 字段校验不足以决定写库；保留撤销，低置信度不猜。
3. 屏幕捕获、长期记忆写入和动作执行由主程序控制。模型说“我看到了”不代表有截图；关观察/过期材料时由上下文与输出策略处理，不能只期待模型自律。
4. 聊天继续比较 Qwen 类中文候选，同时寻找更低体积方案；可选外接大模型保持独立后端、流式取消和屏幕发送开关。未经新集复验不定默认权重、不做正式打包发布。

未验证：真正磁盘冷启动、完整首句时延、长对话/30 天记录与检索、真实 OCR/视觉、真实办公主动陪伴、宠物游戏并行卡顿、进程树内存、消费者 Windows/macOS/Linux 设备和四平台完整包。**G1 仅完成独立 CPU 原型及首轮测量，G2–G6 未接入。**
